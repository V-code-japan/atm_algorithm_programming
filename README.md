# MakeCode Extension

Minecraft Education上で実施するプログラミング学習ゲームのための、**MakeCodeカスタムブロック拡張**です。

児童・生徒がMakeCodeのブロックを組み合わせてプログラムを作成し、そのプログラムをMinecraft内の教材へ送信して実行できるようにします。

現在はATM教材を中心に構成されていますが、将来的には複数のゲーム教材で利用できるプログラミングインターフェースとして拡張することを想定しています。

---

# 1. 概要

本プロジェクトでは、Minecraft EducationのMakeCodeを利用して、児童・生徒がブロックプログラミングを行います。

通常のMakeCodeではMinecraftのエージェント操作などをプログラムしますが、本拡張では**学習対象となるゲームそのものを操作するための専用ブロック**を提供します。

例えばATM教材では、

* ATMのメニューを作成する
* ボタンを追加する
* 特定のイベントを処理する
* 条件によって処理を変更する
* ATM画面を表示する

といった処理をブロックとして組み立てられます。

---

# 2. MakeCodeの役割

システム全体では、MakeCodeは**「学習者がプログラムを作成するためのインターフェース」**として位置付けられます。

```text
┌──────────────────────────────┐
│          MakeCode             │
│                              │
│  カスタムブロックを組み立てる  │
│            ↓                 │
│      プログラムを生成          │
└──────────────┬───────────────┘
               │
               │ Custom Command
               ↓
┌──────────────────────────────┐
│       Minecraft Script API    │
│                              │
│  プログラムを受信             │
│        ↓                     │
│  Parser / Interpreter        │
│        ↓                     │
│  ゲーム内で実行               │
└──────────────────────────────┘
```

MakeCode側ではゲームの実際の処理を行わず、**学習者が作成したプログラムをMinecraft側へ渡すところまで**を主な責務とします。

---

# 3. 学習者から見た利用方法

学習者は基本的に、以下の流れでプログラムを作成します。

```text
課題を確認
    ↓
MakeCodeを開く
    ↓
専用ブロックを組み立てる
    ↓
プログラムを実行・送信
    ↓
Minecraft内で動作確認
    ↓
必要に応じて修正
    ↓
再度実行
    ↓
課題達成
```

このサイクルを繰り返すことで、

**考える → 作る → 試す → 確認する → 改善する**

というプログラミング学習を行います。

---

# 4. カスタムブロック

本拡張では、教材専用のカスタムブロックを定義しています。

ATM教材では、例えば以下のような概念のブロックを使用します。

```text
ATM
├─ メインメニュー
│   ├─ 残高確認
│   ├─ 預け入れ
│   └─ 引き出し
│
├─ イベント
│   └─ 預け入れ
│
└─ 条件
    └─ エメラルドを持っている
```

これらをブロックとして組み合わせることで、プログラミング初心者でもATMの動作を設計できます。

---

# 5. ブロックとプログラムの関係

MakeCode上では、学習者はブロックを操作します。

一方、Minecraft側では、それを専用のプログラム形式へ変換して実行します。

例えば、MakeCode上で、

```text
もし「エメラルドを持っている」なら
    「預け入れ画面」を表示
```

というブロックを作成した場合、内部的にはATM専用の命令へ変換されます。

概念的には、

```text
MakeCode Block
      ↓
IF:HAS_EMERALD
      ↓
SHOW:DEPOSIT
```

のような変換になります。

この変換によって、**ブロックプログラミングとScript API側のInterpreterを接続**しています。

---

# 6. プログラム生成

カスタムブロックによって構築されたプログラムは、Minecraft側で解釈できる形式に変換されます。

現在のATMプログラムでは、命令を `|` で区切る形式を使用しています。

例えば、

```text
RUN|MENU_BEGIN|>MENU_BUTTON:BALANCE|>MENU_BUTTON:DEPOSIT|MENU_END
```

のような文字列になります。

この形式は、Minecraft Script API側の `AtmParser` によって解析されます。

---

# 7. 階層構造の表現

条件分岐などの入れ子構造をMinecraft側へ渡すため、命令の前に `>` を付けて階層を表現します。

例えば、

```text
IF
  SHOW
  RETURN
END_IF
SHOW
```

という構造の場合、

```text
IF
  └─ SHOW
  └─ RETURN
END_IF
SHOW
```

となり、内部的には概念的に、

```text
IF          depth 0
>SHOW       depth 1
>RETURN     depth 1
END_IF      depth 0
SHOW        depth 0
```

として表現されます。

これにより、MakeCode上で作成されたブロックの階層構造を保持したままMinecraft側へ渡すことができます。

---

# 8. Minecraftへの送信

生成されたプログラムは、Minecraft EducationのCustom Command / Script Eventを利用してMinecraft側へ送信します。

処理の流れは、

```text
MakeCode
    ↓
ブロックプログラム
    ↓
ATMプログラムへ変換
    ↓
Custom Command
    ↓
Minecraft Script API
```

となります。

Minecraft側では受信したデータを保存し、必要に応じてParserとInterpreterによって実行します。

---

# 9. Minecraft側との責務分離

MakeCode側とMinecraft Script API側では、それぞれ異なる責務を持たせています。

### MakeCode

* 学習者がプログラムを作る
* ブロックを提供する
* ブロック構造をプログラムへ変換する
* Minecraftへプログラムを送信する

### Minecraft Script API

* プログラムを受信する
* プログラムを保存する
* プログラムを解析する
* プログラムを実行する
* Minecraft内のゲーム状態を変更する

この分離により、MakeCode側でゲームそのものの処理を実装する必要がなくなります。

---

# 10. ATM教材との連携

ATM教材では、MakeCodeとATM Addonを以下のように連携させます。

```text
┌───────────────┐
│    MakeCode   │
│               │
│ ATMブロック    │
└───────┬───────┘
        │
        │ プログラム生成
        ↓
┌───────────────┐
│ Custom Command│
└───────┬───────┘
        │
        ↓
┌───────────────┐
│ ATM Addon     │
│               │
│ AtmParser     │
│      ↓        │
│ AtmInterpreter│
└───────┬───────┘
        │
        ↓
   Minecraft ATM
```

MakeCodeはATMの内部処理を直接実行するのではなく、**学習者が作ったATMプログラムを生成・送信する役割**を担います。

---

# 11. Mission Addonとの関係

MakeCodeはMission Addonとも間接的に連携します。

基本的な流れは、

```text
MakeCode
   ↓
プログラム作成
   ↓
ATM Addon
   ↓
プログラム保存
   ↓
イベント
   ↓
Mission Addon
   ↓
Answerとして保存
   ↓
「できた」
   ↓
達成判定
```

となります。

このため、MakeCodeは**学習者の成果物を作る場所**、ATM Addonは**成果物を実行する場所**、Mission Addonは**成果物を評価する場所**という役割分担になります。

---

# 12. プログラミング学習における特徴

## ブロックによる視覚的なプログラミング

命令を文字として入力するのではなく、ブロックを組み合わせることでプログラムを作成できます。

これにより、プログラミング文法の入力ミスを減らし、処理の構造そのものに集中できます。

## 条件分岐を視覚的に理解

条件ブロックの中に処理ブロックを配置することで、

```text
条件
 └─ 条件を満たした場合の処理
```

という構造を視覚的に理解できます。

## 試行錯誤が容易

作成したプログラムをMinecraft内ですぐに実行できるため、

```text
作る
 ↓
実行
 ↓
結果を見る
 ↓
修正
```

というサイクルを短時間で繰り返せます。

---

# 13. ブロック設計の考え方

カスタムブロックは、単に機能を呼び出すためだけではなく、**学習者がプログラムの構造を理解できること**を重視して設計します。

例えば、

```text
イベント
 └─ 条件
     └─ 処理
```

という構造を、そのままMakeCode上のブロック構造として表現します。

これにより、ブロックの配置そのものがプログラムの処理構造を表します。

---

# 14. 命令体系

ATMプログラムでは、内部的に命令をOpcodeとして管理します。

代表的な命令には、

```text
RUN
END

MENU_BEGIN
MENU_BUTTON
MENU_END

MAIN_BEGIN
EVENT_BEGIN

IF
END_IF

SHOW
RETURN
```

などがあります。

MakeCode側のブロックは、これらの命令を直接文字入力させるのではなく、ブロック操作によって生成します。

---

# 15. 条件

ATM教材では、以下のような条件を利用できます。

```text
HAS_EMERALD
NOT_HAS_EMERALD

HAS_CASH_CARD
NOT_HAS_CASH_CARD

HAS_BALANCE
NOT_HAS_BALANCE
```

MakeCodeでは、これらを学習者が理解しやすいブロックとして提供します。

例えば、

```text
もし「エメラルドを持っている」なら
```

というブロックが、内部的には、

```text
IF:HAS_EMERALD
```

へ変換されます。

---

# 16. メニュー

ATMの画面に表示する機能もブロックとして定義します。

例えば、

```text
BALANCE
DEPOSIT
WITHDRAW
CHARGE
ERROR
```

などがあります。

MakeCodeでは、これらを選択式のブロックとして扱うことで、学習者が内部的な文字列やEnumを意識する必要がないようにします。

---

# 17. エラー処理

MakeCode側では、できるだけ学習者がMinecraft側の内部エラーを意識せずに利用できる構造にします。

例えば、Minecraft側で、

```text
プログラムを実行できない
残高が不足している
お金が不足している
必要なカードがない
```

などの状態が発生した場合、その処理はATM Addon側で行います。

MakeCode側は、**「どのような条件で何をするか」というプログラムの設計に集中できる**ようにします。

---

# 18. 拡張方法

新しい教材を追加する場合は、教材固有のカスタムブロックを追加することができます。

例えば、

```text
ATM
 ↓
ATM Block

自動販売機
 ↓
Vending Machine Block

コンビニ
 ↓
Convenience Store Block
```

のように、教材ごとのプログラミングインターフェースを構築できます。

また、MakeCodeからMinecraftへ渡すプログラム形式を共通化することで、Script API側の仕組みを再利用できます。

---

# 19. 新しい命令を追加する場合

新しい命令を追加する場合は、基本的に以下の流れで対応します。

```text
① MakeCode側にブロックを追加
        ↓
② 内部プログラムを生成
        ↓
③ Minecraft側のOpcodeを追加
        ↓
④ Parserで解析できるようにする
        ↓
⑤ Interpreterで実行処理を追加
        ↓
⑥ 必要に応じてMissionの評価条件を追加
```

このように、**MakeCodeだけを変更すれば新機能が追加できるわけではない**ため、教材全体の構造を確認して実装します。

# 20. プロジェクト全体における位置付け

本プロジェクトでは、3つの主要なシステムが連携します。

```text
                 ┌───────────────┐
                 │    MakeCode   │
                 │               │
                 │ プログラム作成 │
                 └───────┬───────┘
                         │
                         ↓
                 ┌───────────────┐
                 │   ATM Addon   │
                 │               │
                 │ プログラム実行 │
                 └───────┬───────┘
                         │
                         ↓
                 ┌───────────────┐
                 │ Mission Addon │
                 │               │
```

それぞれの役割は、

| システム          | 役割             |

という関係になります。

# 21. 教育的な位置付け

MakeCodeは、本システムにおける**「学習者がプログラミングを行うための入口」**です。

ゲーム内の複雑な処理を学習者から隠し、

```text
何をしたいか
      ↓
どの条件で実行するか
      ↓
どの処理を行うか
```

という本質的な部分に集中できるようにします。

そのため、MakeCode側のカスタムブロックは、単に操作を簡単にするためのUIではなく、**プログラミングの考え方を段階的に学習させるための教材インターフェース**として設計します。

# 22. 今後の拡張

# 23. まとめ

本MakeCode拡張は、Minecraft Education上のプログラミング学習ゲームにおいて、学習者が**視覚的にプログラムを構築するためのインターフェース**です。

MakeCodeで作成したプログラムは、

**カスタムブロック**

↓

**ATM専用プログラム**

↓

**Custom Command**

↓

**Minecraft Script API**

という経路でMinecraftへ送信されます。

Minecraft側では、そのプログラムをParserが解析し、Interpreterが実行します。

また、Mission Addonと連携することで、作成したプログラムを学習成果物として扱い、課題達成の判定にも利用できます。

この構成により、

**「プログラムを作る」**

**「ゲーム内で動かす」**

**「結果を確認する」**

**「修正する」**

**「課題を達成する」**

という一連の学習体験を実現します。
